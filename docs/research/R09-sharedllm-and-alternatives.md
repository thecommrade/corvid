> R09 — SharedLLM & alternatives (verified 2026-08-22, primary sources only) HEADLINE None of the five candidates coordinates stock llama.cpp RPC workers across a Linux+macOS+Windows fleet today. The one that did (SharedLLM) has taken its source private and pivoted to a closed macOS desktop node that auto-joins a public global fleet; GPUStack dropped llama.cpp/llama-box and macOS/Windows workers in v2.0.0; exo 1.x is MLX-only (macOS GPU, Linux CPU, no Windows) and has gone quiet; prima.cpp is a research fork of llama.cpp with its own ring parallelism, no releases, no Windows; Ollama is single-host by design. CORVID's plan to keep a small Python+Postgres coordinator of its own around llama.cpp RPC stands — and CLAUDE.md §3.2's "Phase 5 mandate: evaluate adopting/contributing to SharedLLM" needs an ADR, because there is nothing public to adopt or contribute to. SHAREDLLM (sharedllm.org; source repo MHASK/sharedllm — now private) - What it was: v0.1.0 "public alpha" announced 2026-04-11 — Python coordinator + node daemon (sharedllm-0.1.0-py3-none-any.whl) wrapping stock llama.cpp rpc-server/llama-server binaries (shipped for macOS arm64/Metal, Linux x86_64, Linux arm64, Windows x86_64), HMAC-SHA256 cluster secret, worker discovery, free-memory tracking, split planning, re-planning on node drop. Its own words: only the tiny stories260K model verified end-to-end; larger quants hit an upstream RPC assertion; "If you need a production-grade mesh today, SharedLLM is not that project." - What it is now: github.com/MHASK/sharedllm returns 404 (web and API). The only public artifact is MHASK/sharedllm-releases, whose README says "Source code lives in the private MHASK/sharedllm repo. This repo holds binaries only." Releases v0.1.0 (2026-06-08), v0.2.0 and v0.2.1 (2026-06-10) are macOS Apple Silicon .dmg only; v0.2.0 notes: zero-config, "the app joins the sharedllm.org fleet on first launch", RAM/disk capped at 2 GB. sharedllm.org footer: "An open-source initiative from Naridon, Inc. ... License: AGPLv3 \| Source Code on GitHub", "Currently in beta with live nodes." The AGPL-3.0-or-later claim cannot be verified against any LICENSE file at any tag. No PyPI package (pypi.org/pypi/sharedllm → 404). - Verdict for CORVID: not adoptable, not contributable, and its current direction (closed node, public global fleet, auto-join) conflicts with §1/§5/§7 (friends-only, opt-in, zero public exposure). Keep it as *prior art for design ideas* (HMAC-authenticated RPC proxy, free-memory tracking, re-plan on drop) credited to its blog posts, and record the pivot in an ADR. ## Recommendations for the spec

1. Write an ADR retiring the CLAUDE.md §3.2 'Phase 5 mandate: evaluate adopting/contributing to SharedLLM'. As of 2026-08-22 SharedLLM has no public source (MHASK/sharedllm is private; only macOS .dmg binaries are published), no verifiable licence file, and its v0.2.x direction (zero-config node that auto-joins a public global fleet) conflicts with CORVID §1/§5/§7. Re-scope the §4 row to 'prior art: published design notes (HMAC-authenticated RPC proxy, free-memory tracking, re-plan on node drop) — blog posts only' and cite R09-F1..F7.
2. Keep CORVID's own small coordinator (Python + Postgres, §3.3) as the plan of record for llama.cpp RPC orchestration: no credited project coordinates stock llama.cpp RPC workers across Linux+macOS+Windows today (R09-F2, F12, F21–F22, F26, F34). Borrow SharedLLM's published ideas with credit rather than waiting for a project to adopt.
3. Drop GPUStack from the inference-coordination candidate list for v1 and keep it on the watch list for UI/observability patterns only: workers are Linux-only (macOS/Windows dropped in v2.0.0), NVIDIA needs a CUDA 12.8+-capable driver (solarplexus at 535/CUDA 12.2 fails), llama-box was removed in v2.0.0 and a custom llama.cpp backend cannot span workers (R09-F19–F22).
4. Correct CLAUDE.md §3.2's exo note: exo 1.x is MLX-only (macOS GPU; Linux CPU-only; no Windows; Linux CUDA is an open tracking issue since 2025-12-18), and 'exo-cuda' is an independent GPL-3.0 repo built on the pre-1.0 tinygrad code — not a CUDA port of exo 1.x and under a different licence than upstream's Apache-2.0. Keep exo strictly as a Mac-only experiment branch and note the maintenance-silence signal (no commits since 2026-06-22; issue #2258).
5. Update the prima.cpp watch-list entry: the canonical repo is now https://github.com/OpenCPIL/prima.cpp (MIT; history reset 2026-06-30; no tags/releases; Linux/macOS/Android via Termux; CUDA-only GPUs; Windows and Vulkan on roadmap). Treat as a research prototype to learn from (ICLR 2026), not to depend on.
6. Keep Ollama as the single-node UX bar only. Note for member guides: Ollama v0.32.15 documents NVIDIA minimums of driver 550+ and 570+ for compute capability 5.0–6.2, so the GTX 970 hub on driver 535 is outside Ollama's support — irrelevant to CORVID's llama.cpp path but relevant if a friend compares against Ollama on Maxwell/Pascal hardware (R09-F31).
7. Spec/Phase 1 hygiene from the upstream check: pin llama.cpp to an explicit tag (semver v0.2.0 or a b-build; both schemes are live) and record it in the §4 row; expect the RPC worker binary to be named ggml-rpc-server on builds after 2026-06-27 (commit c299a92c38) — update runbooks/scripts that say rpc-server, and bind it to the Tailscale interface only per the upstream warning (R09-F35–F36).
8. Add/refresh §4 credit rows for the evaluated alternatives at their pinned versions (see credits), including a corrected SharedLLM row (author Naridon, Inc. / MHASK; licence 'AGPL-3.0-or-later (claimed, unverifiable — source private)') and an exo row pinned to v1.0.71 Apache-2.0 with an explicit exo-cuda GPL-3.0 caveat.
