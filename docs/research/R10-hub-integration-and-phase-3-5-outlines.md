> DOSSIER R10 — Hub integration points + Phase 3–5 outlines (researched 2026-08-22, primary sources only; pages fetched with curl and read in full, GitHub raw files at pinned tags). == 1. Tdarr (distributed transcoding) — node model and licence == Architecture: Tdarr_Server is the central process all Nodes connect to; Tdarr_Node runs on the same or other devices and pulls tasks from the Server; nodes exist for Windows, Linux (x64/arm64) and macOS, plus Docker images ghcr.io/haveagitgat/tdarr (server, optional internal node) and ghcr.io/haveagitgat/tdarr_node. Nodes connect OUTBOUND to the server on serverPort (default 8266) and open no inbound port (nodeIP/nodePort obsolete since 2.00.17) — so a friend's node reaches solarplexus over the tailnet with zero inbound exposure. Node config is env vars (override JSON): serverURL (recommended, e.g. http://solarplexus:8266), nodeName, nodeType, priority, apiKey, pathTranslators (JSON only). Two node types: "mapped" (default; node and server must see the SAME media + transcode-cache paths via shares, reconciled with pathTranslators) and "unmapped" (node works from its own cache and uploads/downloads files automatically — but WITHOUT Tdarr Pro it is limited to 10 MB video / 0.1 MB other files, i.e. useless; Pro removes the cap). Unmapped mode also exposes library/cache files via Tdarr's network API, so auth=true + apiKey is advised. NVENC in the node container = --gpus=all + NVIDIA_DRIVER_CAPABILITIES=all. Licence: Tdarr is NOT open source. LICENSE.md is an EULA with tiers Personal Free / Personal Subscription / Business Subscription; it prohibits redistribution, reverse engineering and "any unauthorized use" without permission, is governed by UK law and can be modified "with or without notice". GitHub reports licence "Other/NOASSERTION". The plugin repo (Tdarr_Plugins) is GPL-3.0. Latest binaries per storage.tdarr.io/versions.json: 2.86.01 (docs' updater links point at 2.81.01). Tdarr Pro pricing could not be verified from a static primary page (tdarr.io is a JS app) — left unverified. Meaning for §4: CORVID may *integrate with* a member-installed Tdarr (credit row: "Tdarr — proprietary EULA, Personal Free tier; not redistributed by CORVID") but must never bundle or redistribute it, and the real Phase-3 transcode path across houses is either (a) mapped Tdarr nodes over tailnet SMB/NFS shares from solarplexus, or (b) CORVID's own ffmpeg-in-a-capped-container jobs, which avoids the proprietary dependency and the Pro paywall entirely. Recommend (b) as the Phase-3 default and Tdarr as an optional hub integration. == 2. Immich remote machine learning == Immich v3.1.0 (2026-07-29, AGPL-3.0). The immich-machine-learning container can run on a different host; the server sends image previews to it over HTTP; the ML container "does not persist this data", and — the docs' own danger note — "as an internal service, the machine learning container has no security measures whatsoever". Compose: image ghcr.io/immich-app/immich-machine-learning:${IMMICH_VERSION:-release}[-cuda], volume model-cache:/cache, port 3003; then Admin → Machine Learning Settings → Add URL http://ip:3003. Smart Search + Face Detection go remote; Facial Recognition stays server+DB. Multiple URLs are tried sequentially (no load balancing); adding a URL keeps local fallback, replacing it means jobs fail (and must be retried) when the remote is down. Both hosts should run the same IMMICH_VERSION. CUDA backend: compute capability ≥ 5.2, official driver ≥ 545 (CUDA 12.3), NVIDIA Container Toolkit on Linux (not needed under WSL2); Linux and Windows/WSL2 servers only; hwaccel.ml.yml cuda = deploy.resources.reservations.devices {driver nvidia, count 1, capabilities [gpu]}. Multi-GPU via MACHINE_LEARNING_DEVICE_IDS + MACHINE_LEARNING_WORKERS, each GPU must hold all models. Fleet impact: solarplexus (driver 535 / CUDA 12.2, GTX 970 CC 5.2) meets the CC floor but NOT the ≥545 driver floor — it cannot host the -cuda ML image without a driver upgrade; the RTX 2070 Super laptop (CC 7.5) and RTX 3050 node (CC 8.6, CUDA 13.1) can. Bind 3003 to the tailnet IP only (no auth exists), and pin versions. == 3. Docker resource caps for batch jobs == Containers are unconstrained by default. Hard caps: --memory (min 6m) with --memory-swap set EQUAL to it to deny swap (unset = container may use as much swap again as memory; -1 = unlimited), --memory-reservation is soft; do not use --oom-kill-disable without -m. CPU: --cpus="1.5" ≡ --cpu-period=100000 --cpu-quota=150000; --cpuset-cpus pins cores; --cpu-shares is soft. Check `docker info` for "WARNING: No swap limit support". GPU: --gpus all \| device=0 \| device=<UUID> \| '"device=0,2"' requires the NVIDIA driver + NVIDIA Container Toolkit (configure with `sudo nvidia-ctk runtime configure --runtime=docker && sudo systemctl restart docker`); "NVIDIA GPUs can only be accessed by systems running a single engine"; capabilities via --gpus 'all,capabilities=utility'. Host protection flags from the docker run reference: --read-only (root fs RO), --tmpfs, --pids-limit, --cap-drop, --security-opt no-new-privileges (su/sudo stop working). Docker Engine by default "drops all capabilities except those needed, an allowlist instead of a denylist approach"; best practice is to remove all capabilities except those explicitly required. Docker Engine (moby) is Apache-2.0; Docker Desktop is free for personal use / small business (<250 employees AND <$10M revenue) under the Docker Subscription Service Agreement. NVIDIA Container Toolkit v1.20.0 is Apache-2.0; its tested-platform table lists Ubuntu 22.04/24.04/26.04, Debian 11, RHEL 8/9/10, Amazon Linux, SUSE — Arch is not listed, though "Releases can work on more platforms than indicated". ## Main-session notes

- The hub already runs Tdarr, Immich (no ML container) and Caddy (R00/status.md) — the first Phase 3 workloads are ready-made.

## Recommendations for the spec

1. Phase 3 default transcode path: CORVID's own ffmpeg-in-a-capped-container job (open, credit-clean) rather than Tdarr; treat Tdarr as an optional, member-installed hub integration. Tdarr's EULA forbids redistribution, so CORVID must never bundle Tdarr binaries/images or wrap its installer; link to official downloads only and record it in §4 as 'proprietary EULA, Personal Free tier, not redistributed'.
2. If Tdarr is used: run Tdarr_Server on solarplexus bound to the tailnet IP (serverIP/serverBindIP), set auth=true and per-node apiKey, and use MAPPED nodes over tailnet-only SMB/NFS shares with pathTranslators — unmapped nodes are capped at 10 MB files without Tdarr Pro and expose library/cache via the network API.
3. Immich photo brain: run ghcr.io/immich-app/immich-machine-learning:${IMMICH_VERSION}-cuda on the RTX 2070 Super laptop or RTX 3050 node (both meet CC>=5.2 and driver>=545); solarplexus (driver 535 / CUDA 12.2) cannot host the CUDA image until upgraded to >=545 (GTX 970 CC 5.2 would then qualify). Bind port 3003 to the tailnet interface only (the ML service has no auth), pin both hosts to the same IMMICH_VERSION (currently v3.1.0), and add the remote URL (keep local fallback) rather than replacing it; one remote URL only since Immich does no load balancing.
4. Batch-job container template (enforced locally by the agent, §5.3/§5.5): docker run --rm --cpus=<owner cap> --memory=<cap> --memory-swap=<same value> --pids-limit=<n> --read-only --tmpfs /tmp --mount type=bind,src=<scratch>,dst=/work --cap-drop ALL --security-opt no-new-privileges [--gpus device=<idx>] <image>; add a CI/agent preflight that checks `docker info` for 'WARNING: No swap limit support' and that the NVIDIA Container Toolkit is configured (nvidia-ctk runtime configure --runtime=docker).
5. Windows member guide (WSL2 path): install only the Windows NVIDIA driver (never a Linux driver in WSL), `wsl --install` + `wsl --update`, Docker Desktop (free for personal use) with the WSL2 backend; expect `--gpus all` only (no per-GPU indexing) and no NVML utilization queries; require Pascal-or-newer GPUs (Maxwell unsupported in WSL2). Validate with the nbody cuda-sample container.
6. Arch/EndeavourOS laptop: NVIDIA Container Toolkit is not in NVIDIA's tested-platform table — verify with a spike before relying on --gpus there; Ubuntu hub and Debian-family nodes are covered.
7. gVisor: adopt as the documented Phase-4/5 upgrade path for Linux/WSL2 batch nodes (install via apt repo; --runtime=runsc; systrap default needs no KVM). Do not enable by default in v1 (friends-trust model). GPU-in-gVisor is a spike: nvproxy requires a strict driver-version match (check `runsc nvproxy list-supported-drivers` against each node's exact driver) and officially supports datacenter GPUs only; consumer Turing/Ampere 'likely' work, Maxwell (GTX 970) is not on any supported microarchitecture.
8. Folding@home: founder creates 'team CORVID' once in Web Control (needs one free F@h Account), publishes the team number in the member guide; each member installs the official client themselves (the agent must NOT silently install or bundle F@h — rules/EULA forbid it), picks their own username/passkey (passkey stays private), and uses F@h's built-in 'Only When Idle' + CPU slider + per-GPU toggles, which already satisfy §5. Linux/headless members use /etc/fah-client/config.xml with an account token; Windows/macOS installers are signed, Linux packages are not (download from foldingathome.org only). Thank-you board can pull daily_team_summary.txt, never scrape live stats.
9. ADR for Phase 5: decide (a) Tdarr integration vs native ffmpeg jobs, (b) hub driver upgrade to >=545 (unlocks Immich CUDA on solarplexus; re-check gVisor nvproxy list after), (c) gVisor enablement criteria (when a workload is less than fully trusted).
10. §4 credit rows to add on adoption: Immich (AGPL-3.0), Docker Engine (Apache-2.0), Docker Desktop (Docker Subscription Service Agreement, free personal tier — Windows members), NVIDIA Container Toolkit (Apache-2.0), gVisor (Apache-2.0), Folding@home client (GPL-3.0); Tdarr only as a non-redistributed proprietary integration, Tdarr_Plugins (GPL-3.0) only if CORVID writes plugins.

## Open questions

- Tdarr Pro price/terms and whether a friends co-op counts as 'personal' under the EULA; whether the Personal Free tier limits node count (not stated in docs fetched).
- Is Tdarr mapped-node transcoding over tailnet SMB/NFS across houses acceptable on home upload bandwidth, or does the 'files must be on a shared filesystem' requirement make Tdarr a single-LAN tool for CORVID?
- Immich remote-ML over the tailnet: is tailnet-only binding sufficient given the container has no auth, or should CORVID front it with Tailscale serve/ACLs restricted to solarplexus?
- Does NVIDIA Container Toolkit + Docker --gpus work on the Arch/EndeavourOS laptop (not in NVIDIA's tested table)?
- Does gVisor nvproxy actually run CUDA workloads on GTX 970 (Maxwell) or RTX 2070 Super (Turing consumer)? Only datacenter GPUs are officially supported.
- Why does the Folding@home debian-stable-64bit package directory list 8.1.18 while other platforms are at 8.5.6 — is there a newer apt repo path members should use?
- stats.foldingathome.org was unreachable from the research host; confirm the team leaderboard/team page fields from another network before writing the member guide.
- Windows members without WSL2 (or with Maxwell GPUs): do they contribute CPU-only Docker jobs, or only inference/F@h?
- Which Docker flag set survives gVisor (runsc) unchanged — --pids-limit, --read-only, --tmpfs, --cap-drop are listed as broadly compatible but should be spiked before an ADR.
