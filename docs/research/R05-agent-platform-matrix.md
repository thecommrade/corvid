Linux (full depth) ### 1.1 Running the agent: systemd --user + linger - The agent should be a **user service** (`~/.config/systemd/user/corvid-agent.service`, `WantedBy=default.target`), not a system service: user units are loaded from `$XDG_CONFIG_HOME/systemd/user` (~/.config/systemd/user), `/etc/systemd/user`, `$XDG_DATA_HOME/systemd/user`, `/usr/lib/systemd/user` (R05-F2); `default.target` is "the main target of the user service manager ... a real unit, not an alias" (R05-F3). - `loginctl enable-linger USER`: "a user manager is spawned for the user at boot and kept around after logouts. This allows users who are not logged in to run long-running services" (R05-F1). Linger is what makes the hub (solarplexus) and any always-on node keep serving after logout. Founder laptop already has Linger=yes (local test). - Why user-level rather than root: the owner's own manager is "the final authority" (CLAUDE.md §5.3) and `systemctl --user stop corvid-agent` / `systemctl --user kill` is a kill switch that needs no sudo. ### 1.2 Idle detection — the honest picture (Wayland vs X11, GNOME vs KDE) There is no single Linux idle API. What actually works, per desktop: - **logind IdleHint** (`loginctl show-session <id> -p IdleHint`, D-Bus `org.freedesktop.login1` Manager/Session `IdleHint`, `IdleSinceHint`): logind only *reflects* what sessions report; `Session.SetIdleHint()` "is called by the session object to update the idle state of the session whenever it changes", and logind.conf warns IdleAction "requires that user sessions correctly report the idle status" (R05-F13). **GNOME does report it** — gnome-session 50.1 calls `SetIdleHint` (R05-F14). **KDE Plasma apparently does not**: a GitHub code search across org:KDE finds no caller, only copies of the interface XML (R05-F15, unverified/negative evidence). ⇒ IdleHint is trustworthy on GNOME, not on Plasma. - **KDE `org.freedesktop.ScreenSaver.GetSessionIdleTime`** (the seed's suggestion): kscreenlocker v6.7.4 explicitly returns `NotSupported` ("GetSessionIdleTime is not supported on this platform") when the platform is Wayland; it works only on X11 (R05-F16; reproduced on the founder's Plasma-Wayland laptop). `GetActive` (screen locked?) still works on both. - **GNOME Wayland**: `org.gnome.Mutter.IdleMonitor` at `/org/gnome/Mutter/IdleMonitor/Core` — `GetIdletime()` (ms) and `AddIdleWatch(interval)` → `WatchFired` signal (mutter 50.4, R05-F17). Plain D-Bus, trivial from Python. - **Compositor-neutral Wayland**: `ext-idle-notify-v1` (wayland-protocols 1.45, MIT): `ext_idle_notifier_v1.get_idle_notification(timeout_ms, seat)` → `idled`/`resumed`; v2 `get_input_idle_notification` ignores idle inhibitors (R05-F18). KWin v6.7.4 implements it; KIdleTime's Wayland plugin consumes it (R05-F19). Mutter: no implementation found (unverified). Needs a real Wayland client (pywayland or a tiny C/Qt helper), not D-Bus. - **X11**: XScreenSaverQueryInfo `idle` = "milliseconds since the last input was received from the user on any of the input devices"; `xprintidle` (0.3.0, GPL-2.0-only) prints exactly that (R05-F20). - **Design consequence**: implement idle as a *presence provider chain* with an explicit "unknown" state: Mutter IdleMonitor → ext-idle-notify (KDE/wlroots) → logind IdleHint → XScreenSaver/xprintidle → unknown. When unknown, the agent must fall back to a *load-based* politeness signal (CPU/IO pressure) and say so in the UI; never silently treat unknown as idle. ### 1.3 Battery / AC - **UPower** (system bus `org.freedesktop.UPower` at `/org/freedesktop/UPower`): `OnBattery` (b) "Indicates whether the system is running on battery power", `LidIsClosed`; per-device `State` (1 Charging, 2 Discharging, 4 Fully charged), `Percentage` (R05-F21). Founder laptop: upower 1.91.3, on-battery=no (local test). - **sysfs fallback** (no daemon needed): `/sys/class/power_supply/<name>/type` (Mains/Battery), `online` (AC present), `status` ∈ {Unknown, Charging, Discharging, Not charging, Full}, `capacity` 0–100 (R05-F22). Founder laptop: ADP1 type=Mains online=1; BAT1 status=Not charging capacity=94 (local test). - Cross-platform shortcut: `psutil.sensors_battery()` → (percent, secsleft, power_plugged) (R05-F53) — same call on all three OSes. ### 1.4 Resource caps — cgroup v2 via systemd, with live changes - `systemd-run --user [--scope] -p CPUQuota=20% -p MemoryMax=2G ... -- cmd` starts a transient unit; `-p` takes "the same format as systemctl's set-property" (R05-F8). `CPUQuota=20%` "ensures that the executed processes will never get more than 20% CPU time on one CPU" (cpu.max); `MemoryHigh=` is "the main control mechanism", `MemoryMax=` "the last line of defense" (OOM-kills inside the unit); `IOWeight=` 1–10000, default 100 (R05-F4–F6). `CPUWeight=idle` exists for "idle scheduling" (R05-F4 note) and systemd.exec offers `Nice=`, `CPUSchedulingPolicy=idle`, `IOSchedulingClass=idle`, `OOMScoreAdjust=` (R05-F27). - **Live changes**: `systemctl [--user] set-property UNIT CPUQuota=10% MemoryMax=1G` — "The changes are applied immediately, and stored on disk for future boots, unless --runtime is passed" (R05-F7). ## Main-session notes

- Linux agent v0 mechanisms are measured (S-06) and designed in the Phase 2 spec (`corvid.slice`, provider chain with UNKNOWN, psutil battery); macOS/Windows rows are documentation only until a member with that OS volunteers (package spec §6.1).

## Recommendations for the spec

1. Linux agent = a per-user systemd service (~/.config/systemd/user/corvid-agent.service, WantedBy=default.target) plus `loginctl enable-linger` on always-on nodes (hub, optiplex); never a root service. Kill switch = `systemctl --user stop corvid.slice` (all CORVID work lives in one user slice) — KillMode=control-group guarantees nothing survives.
2. Run every job as a transient unit: `systemd-run --user --slice=corvid.slice -p CPUQuota=<n>% -p MemoryHigh=<x> -p MemoryMax=<y> -p CPUWeight=idle -p IOSchedulingClass=idle -p Nice=19 ...`; implement the owner's live slider as `systemctl --user set-property corvid.slice CPUQuota=... MemoryMax=...` (applied immediately, persisted unless --runtime).
3. Document the io-delegation gotcha in the Linux install guide: CPU/RAM caps work unprivileged; IOWeight/IOReadBandwidthMax need a one-time sudo drop-in `/etc/systemd/system/user@.service.d/corvid.conf` with `[Service]\nDelegate=pids memory cpu io` (spike this on the hub; until then rely on IOSchedulingClass=idle).
4. Build idle detection as a provider chain with an explicit UNKNOWN state: (1) org.gnome.Mutter.IdleMonitor.GetIdletime (GNOME, D-Bus), (2) ext-idle-notify-v1 client (KDE/wlroots Wayland — small helper; spike pywayland vs a 50-line C/Qt binary), (3) logind IdleHint (trust only when provider 1 is present/GNOME), (4) XScreenSaver/xprintidle (X11), (5) UNKNOWN → use load/pressure heuristics and show 'presence unknown' in the status page. Do not use org.freedesktop.ScreenSaver.GetSessionIdleTime (NotSupported on Plasma Wayland).
5. Battery/AC: use psutil.sensors_battery() as the one cross-platform call; on Linux fall back to /sys/class/power_supply/*/online + status when psutil is unavailable; default policy run_on_batteries=false, and on AC-loss pause immediately (don't wait for the next heartbeat).
6. GPU policy for the spec: treat GPU as all-or-nothing per job/time-window — no compute shares on GeForce (no MIG; MPS is Tesla/Quadro-targeted and Linux-only; cgroup v2 has no GPU controller). Implement 'GPU off' via DeviceAllow/DevicePolicy=closed or CUDA_VISIBLE_DEVICES='' on the job unit, and VRAM ceilings via the coordinator's --tensor-split plan (ggml-rpc-server b10581 has no --mem flag). Owner-side nvidia-smi -pl power caps are root-only — document as optional sudo step, never required.
7. macOS agent = LaunchAgent plist in ~/Library/LaunchAgents with KeepAlive=true, RunAtLoad=true, ProcessType=Background, LowPriorityIO=true, Nice=10+; spawn jobs via `taskpolicy -c background` (and -m MiB for a memory limit); idle via IOHIDSystem HIDIdleTime (ioreg) + org.freedesktop.ScreenSaver-equivalent lock check; battery via pmset -g batt/psutil. Defer SMAppService/.app bundle until a tray UI exists.
8. Windows agent = per-user Scheduled Task (ONLOGON, /it, highest-available run level not required) running the Python agent in the user session — NOT a Windows service — because GetLastInputInfo is session-scoped and services live in Session 0. Use Job Objects for each job (CPU hard cap via CpuRate, JobMemoryLimit, KILL_ON_JOB_CLOSE, TerminateJobObject as kill switch) and register GUID_ACDC_POWER_SOURCE / GUID_SESSION_USER_PRESENCE notifications; also set Task Scheduler StopIfGoingOnBatteries for belt-and-braces.
9. Packaging v1 (Phases 2–3): Python 3.12+ app published as a wheel, installed with `uv tool install corvid-agent` (uv manages Python via python-build-standalone); one install script per OS that also registers the systemd/launchd/Task-Scheduler unit; `uv tool upgrade` for updates. This keeps the $0 budget (no Apple $99/yr, no Trusted Signing $9.99/mo) and avoids Gatekeeper/SmartScreen dialogs for our own code. Revisit PyInstaller/Briefcase single binaries in Phase 4 only if non-technical onboarding fails; budget $99/yr (Apple) + $9.99/mo (Azure Trusted Signing, individual identity requires US/Canada) if that day comes, and note PyInstaller needs per-OS build machines.
10. Opt-in schema (coordinator DB + agent config): boolean roles {inference_host, batch_jobs, gpu_allowed, disk_donate}, caps {cpu_quota_pct, allowed_cpus, mem_high, mem_max, io_weight\|io_idle, vram_cap_mb (coordinator-enforced)}, politeness {run_if_user_active=false, idle_minutes, run_on_batteries=false, suspend_cpu_usage_pct, schedule windows} — borrow BOINC's names so the semantics are already documented; the agent enforces locally and reports the effective policy in its heartbeat.
11. Add ADR: 'Idle/presence detection is best-effort and desktop-specific; UNKNOWN presence never counts as idle' and 'GPU sharing is temporal, not spatial, on consumer NVIDIA'.
